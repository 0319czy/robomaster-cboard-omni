# 数据采集与分析

## 两条记录链路

`capture_drive.py`通过SWD读取低频发布状态，发布上限10Hz、现场有效约6.7Hz。适合状态和慢变化，不适合识别两圈/秒运动中的精确相位。

`capture_fast.py`配置板内记录器，在主循环中同步保存1000帧，每帧96字节。默认10ms抽样，100Hz、跨度9.99秒；录满冻结后才经SWD导出。缓冲不会循环覆盖。

```bash
python3 tools/capture_fast.py --timeout 600 --ready-file /tmp/chassis-fast.ready
# ready文件出现后，操作者通过遥控触发自旋并叠加平移
python3 tools/analyze_mixed_drive.py logs/fast_capture_时间戳.json --out-prefix logs/本次试验
python3 tools/identify_translation_lag.py logs/fast_capture_时间戳.json
```

命令默认等待合成旋转指令超过1rad/s再开始；`--immediate`用于静止基线。记录命令只布置观察，不启动电机。独占采集进程退出后，可运行 `capture_fast.py --cancel`冻结记录器；不能在另一个OpenOCD占用下载器时并行运行。

## 每帧字段

固定布局由include/drive_trace.h定义，版本1，96字节：
- 时间戳、控制周期、IMU陈旧时间；
- 四轮目标、原始与滤波转速；
- 本轮PI电流输出、最近提交CAN的电流、C620反馈转矩电流；
- 陀螺XYZ、车体航向、平移参考航向、相对参考角；
- 平移/合成旋转指令、状态、故障、各轮反馈年龄；
- 主循环耗时、控制周期序号和CAN发送失败计数。

高速记录Z轴已扣零偏；X/Y是传感器坐标值。C620反馈电流不是直接相电流测量。主机接收的CAN与IMU仍有自身物理采样时刻，陈旧时间需一起检查。本版未单独记录SB和右摇杆原始输入，阶段划分使用合成旋转指令。

主机只在冻结状态导出，三次RAM读回的后两次必须一致。配置采集前先比对板上Flash与ELF配套BIN，防止用错结构地址。

## 分析边界

轮速逆解和陀螺用于估计参考系速度，不是独立地面定位。几何误差、轮胎滑移或悬挂变化均可能影响结果。100Hz比旧记录更适合低频动态辨识，但仍不能排除超过其带宽的振动。

滞后辨识只取全速且局部杆量稳定的样本，拟合闭环平移通道的等效响应；不能把拟合时间直接解释为某个单独传感器延迟。预测补偿后的“下发目标逆解”会主动提前，评估效果应比较轮速估计速度与操作者请求，而非只看轮速对下发目标的误差。

样例数据与复现命令见 [data/README.md](data/README.md)。
