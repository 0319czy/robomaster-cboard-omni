# 架构与代码规范

## 模块边界

| 模块 | 职责 |
|---|---|
| main.c | HAL时钟/CAN接入、主循环调度、控制源优先级、诊断快照 |
| rc_serial.c | USART3的SBUS接收、字节错误和帧校验 |
| rc_drive.c | 通道映射、SB斜坡、参考航向、平移预测角 |
| omni_x45.c | 四全向轮混控、坐标变换、轮速比例限幅；不访问硬件 |
| chassis_control.c | 四轮PI、制动、故障状态机和锁存 |
| bmi088.c | HAL SPI传感器驱动 |
| drive_trace.c | 一次性同步记录、触发、抽样和冻结；不改变控制目标 |
| uart_teleop.c | 备用ASCII串口入口，当前非主要操作链路 |
| rc_pwm/rc_dbus/rc_sniff | 历史输入诊断；DBUS/sniff初始化不在当前主路径启用 |

## 控制顺序

主循环约2ms一次：复制同一批CAN反馈 → 读取IMU → 复制SBUS帧 → 校验接收/IMU/解锁条件 → 更新SB斜坡与参考航向 → 计算预测后的平移坐标变换角 → 混控 → 四轮速度闭环 → 约4ms发送CAN → 高速记录 → 低频状态发布。

手动停车和锁存故障优先于动作入口。全回中连续500ms后才允许遥控解锁。右摇杆只通过独立转向量更新参考航向；SB不写该参考。

## 适度封装

硬件协调集中在main；不访问外设的算法独立成小模块，便于主机测试。工具仅抽取共享的下载器配置、访问锁和绘图字体，避免为单次分析建立复杂框架。

C/C++遵循根目录 `.clang-format`：4空格、100列、统一括号与换行，不重排include。Python遵循 `pyproject.toml` 中的Black配置。第三方历史USB源码不自动重排。

新增外设操作使用HAL；中文注释说明物理方向、单位、时间约束、失效路径和选择理由。避免注释重复代码或留下与常量冲突的旧参数。修改控制逻辑需运行对应主机回归；硬件验收与主机测试分别记录。

## 主要单位

转速为电机转子rpm；遥控速度为mm/s；旋转指令为mrad/s；几何计算使用m、rad；时间戳为HAL毫秒计数。不要把轮轴rpm、转子rpm和整车圈/秒混用。
